# LLM 解释层集成

**对应 commit:** （本次）
**日期:** 2026-04-03

## 需求

在蹦床分析完成后，将结构化结果发送给千问大模型（通过 OpenAI 兼容接口），获取自然语言分析。后端流式转发、清洗、分段；前端先显示流式文本再自动切换为结构化卡片。

## 架构

```
分析完成 → 前端点击"开始 AI 分析"→ GET /api/video/llm_analysis/<id> (SSE)
→ 后端构建 AnalysisReport → 填充 prompt → 调用千问 (stream=True)
→ 逐 chunk 清洗后 SSE 推送 → 流结束后分段 + 缓存 → 发送 done event
→ 前端：流式文本折叠 → 四张结构化卡片淡入
```

## 新建文件

### `trampoline/llm_service.py`

四个组件：
1. **AnalysisReport** dataclass — 从 video_analyses dict 构建，含未来扩展字段（landing_points, form_scores, rotation_data, extra_sections）
2. **build_prompt()** — 系统提示词（回答边界 + 语气 + 固定四段标题）+ 用户数据
3. **stream_llm_analysis()** — 读取环境变量 `QWEN_API_KEY`/`QWEN_BASE_URL`/`QWEN_MODEL`，用 openai SDK 流式调用
4. **clean_chunk() / segment_response()** — 去空白、合并换行、按 `## ` 标题切分为 dict；30 分钟内存缓存

### `tests/test_llm_service.py`

18 个单测覆盖 report 构建、prompt 生成、chunk 清洗、response 分段、缓存。

## Prompt 设计要点

- **回答边界**：只基于给定数据，不猜测未检测的动作，数据不足说"数据不足"
- **语气**：面向运动员或教练
- **固定输出格式**：`## 整体表现` / `## 主要问题` / `## 逐跳点评` / `## 改进建议`
- **可扩展**：`extra_sections` 字段可拼入任意未来数据

## 后端处理

A. 流式 chunk 清洗：过滤空 chunk、合并连续换行
B. 完整结果缓存（30 分钟，按 video_id）
C. 结构分段：按 `## ` 标题切为 4 段 dict

## 前端 UX

1. 分析完成后显示"开始 AI 分析"按钮
2. 点击后显示流式文本框 + 脉冲"正在分析..."
3. 流结束后文本框折叠（CSS transition）、四张卡片淡入
4. "展开原文"按钮可切换查看原始流式文本

## 可扩展性

后续加落点分析/动作评分等，只需在 AnalysisReport 加字段 + extra_sections 拼入 prompt，LLM 层和前端无需改动。
