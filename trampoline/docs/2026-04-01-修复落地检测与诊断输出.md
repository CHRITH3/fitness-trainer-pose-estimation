# 修复落地检测与诊断输出

**对应 commit:** d12dd25
**日期:** 2026-04-01

## 问题

1. **落地检测方向反转**：代码检测"上升→下降"零交叉点（= 跳跃最高点），而不是"下降→上升"零交叉点（= 实际落床点）。导致 flight 阶段仅覆盖上升半段，下降半段被错误归入 contact。
2. **速度判定无防噪声机制**：仅比较两帧间速度变化，单帧噪声即可触发误判。
3. **脚踝 EMA 基线可信度未知**：运动员大部分时间在空中，EMA 可能漂移。
4. **死代码**：`_ankle_y_contact_max` 被赋值但从未在判断条件中使用。

## 修复内容

### 1. 落地检测方向修正

| 原代码（错误） | 修正后 |
|---------------|--------|
| `prev_velocity < -threshold AND velocity >= 0` | `prev_smoothed > threshold AND smoothed <= 0` |
| 检测：上升→下降（最高点） | 检测：下降→上升/停止（落床点） |

### 2. 速度平滑

在原始有限差分速度之上叠加 3 帧移动平均：

```python
self._velocity_history = deque(maxlen=3)
smoothed = sum(self._velocity_history) / len(self._velocity_history)
```

所有零交叉检测改用 `smoothed` 而非 raw velocity，起跳检测也改用 smoothed。

### 3. 诊断 CSV 输出

`JumpDetector` 新增 `_diagnostic_log` 列表和 `dump_diagnostics(path)` 方法。每帧记录：

| 字段 | 说明 |
|------|------|
| frame | 视频帧号 |
| time_s | 时间（秒） |
| com_y | 重心 y（归一化） |
| ankle_y | 脚踝 y（归一化） |
| velocity | 原始速度（归一化 y/秒） |
| smoothed_velocity | 3 帧平滑速度 |
| ankle_ema | 脚踝 EMA 基线 |
| phase | 当前阶段 |
| event | 触发的事件（landing/takeoff/空） |

`video_processor.py` 在蹦床视频处理完成后自动调用，输出 `{video_id}_diagnostics.csv`。

### 4. 删除死代码

移除 `_ankle_y_contact_max` 相关赋值。

## 验证

用 2160x3840 25fps 视频测试，成功检测 10 次跳跃：4x Straight, 4x Straddle, 2x Tuck。Landing/takeoff 事件在 CSV 中时间间隔合理。
