# 2026-04-20 视频页改版执行说明

## 任务背景

本轮工作基于：

- `.omx/plans/ralplan-video-analysis-direct-calibration-and-panel-layout.md`
- `.omx/plans/prd-video-analysis-direct-calibration-and-panel-layout.md`
- `.omx/plans/test-spec-video-analysis-direct-calibration-and-panel-layout.md`

目标是在**不改变现有蹦床分析语义**的前提下，解决视频分析页两个核心问题：

1. 单帧标定必须滚动到下方重复画面，交互割裂。
2. 右侧面板过长，桌面端需要频繁滚轮拖动才能看到关键信息。

## 为什么这次要这样改

这次改版不是单纯“调 UI 好不好看”，而是在修两个真正影响使用体验的问题：

- 用户明明已经在主视频里看到了暂停画面，却还要滚到下方另一块区域重新点一次
- 右侧信息太长，导致用户要不断上下滚动才能找到关键结果

所以这次设计重点不是“多加信息”，而是两条原则：

1. **标定要尽量无感切换**
2. **摘要信息优先展示，详细信息按需展开**

## 本次实现结果

### 1. 标定改为直接在主视频画面上完成

- 上传并进入待标定态后，不再默认激活一个“首帧草稿”。
- 用户可以先在主视频里：
  - 播放
  - 暂停
  - 拖动进度
- 点击 **“添加当前帧标定”** 后，才会在主视频上方开启可点击 overlay。
- 用户直接在上方暂停视频画面上点击四个角点完成标定。
- 下方区域仅保留：
  - 操作按钮
  - 说明文案
  - 标定 chips
  - 关键帧列表

### 2. 去掉下方重复标定画面

- 不再显示单独的下方 `corner-canvas` 标定图。
- 主视频与标定交互使用同一视觉表面，避免“跳到另一张图上去点”的感觉。

### 3. 右侧面板重排为桌面优先的紧凑布局

右侧改为双列信息区：

- 第一列：
  - 实时统计
  - 落点图
- 第二列：
  - 分析报告
  - AI 分析
  - 过程反馈

这样能在常见桌面浏览器高度下更集中地展示关键信息。

## 实时统计调整

实时统计缩减为 4 项：

1. 跳次
2. 当前跳滞空时间
3. 动作
4. 落点坐标 + conf

其中：

- 如果当前处于 flight，则优先显示当前实时数据；
- 如果当前没有有效实时值，则回退到**最近一次有效跳**的数据；
- 落点图与视频侧的落点数据来源保持同一家族语义。

## 分析报告与反馈调整

### 分析报告

默认只显示摘要：

- 分析类型
- 总跳次
- 动作分布
- 处理耗时

逐跳明细被折叠到按钮 **“每跳详细数据”** 下。

### 过程反馈

- 高度压缩为短滚动区
- 页面上优先看见最新几条
- 避免反馈区域把整页撑长

## 后端配套调整

为支持新的紧凑 UI，状态接口新增了**加法式字段**，未改原有跳跃分割/落地语义：

- `phase`
- `current_flight_frames`
- `current_flight_duration_s`
- `latest_landing`
- `landings`
- `fps`
- `video_fps`

这些字段只用于让前端正确展示“当前值 / 最近一次有效值”，不改变既有分析结果定义。

## 这次开发方法上有什么值得学

### 1. 先改交互主路径，再改视觉细节

这次不是先去调颜色、调边框，而是先解决：

- 标定是不是还要跳到另一张图上
- 右侧信息是不是必须靠页面滚动才能看到

这说明一个很重要的开发顺序：

> 用户最痛的地方，优先看“流程是否顺”，再看“视觉是否精致”。

### 2. 新状态字段采用“加法式扩展”比“重做返回结构”更稳

状态接口没有推翻旧字段，而是新增：

- `phase`
- `current_flight_duration_s`
- `latest_landing`
- `landings`

这是一种很稳的后端迭代方式：

- 老逻辑不容易被打断
- 新 UI 有足够数据可用
- 前端可以逐步切换到新字段

### 3. 统计区像“带回退的锁存寄存器”

这次最值得学习的一个代码思路，是 `video_analysis_helpers.js` 里把“当前值优先，没有就回退到最近一次有效值”的规则收敛成纯逻辑。

如果你有 MCU C 背景，可以把它想成：

- 有实时寄存器值就读实时值
- 实时值暂时无效时，就回退到最近一次锁存的有效值

这样做的好处是：

- UI 不会在没有当前 flight 数据时到处显示 `--`
- 判断逻辑集中在一处
- 页面不会到处写重复的 if / else

### 4. “摘要优先、详情折叠”比“所有信息平铺”更适合右侧面板

右侧空间本来就有限，所以这次没有继续堆卡片，而是把逐跳明细折叠起来，把摘要放在第一层。

这背后的方法论其实很通用：

- 第一层先回答“当前最想知道什么”
- 第二层再回答“如果我想深挖，去哪里展开”

## 额外说明

本轮还专门修复了两个容易被忽略的交互问题：

1. **overlay 不会在待标定一进入时就挡住视频控件**
   - 只有在用户明确点击“添加当前帧标定”后才激活可点击层。

2. **不会默认拿 frame 0 当作可误保存草稿**
   - 草稿必须由用户显式选择当前帧后才建立。

## 后续建议

如果下一轮还要继续优化视频分析页，优先级建议如下：

1. 增加真实浏览器人工点测（不同桌面分辨率）
2. 如果落点图后续还会复用，可继续抽出独立 renderer
3. 如果后续还会扩展更多右侧信息，建议继续保持“摘要优先、详情折叠”原则

这篇文档作为模板最值得保留的一点，是它同时讲清楚了：

- 为什么要改
- 怎么改
- 数据是怎么配合 UI 的
- 改完以后怎么验证
- 后续还能怎么继续优化
