# 关键帧补标实现与复核记录

## 背景

本轮工作对应 `.omx/plans/ralplan-trampoline-keyframe-line-minimap.md`、`.omx/plans/prd-trampoline-keyframe-line-minimap.md` 与 `.omx/plans/test-spec-trampoline-keyframe-line-minimap.md`，目标是在 trampoline 上传分析流程中补齐：

1. **分析前多关键帧床面补标**，避免长视频/手持视频仅靠首帧标定导致后续漂移。
2. **marker line 最佳努力高亮**，帮助教练理解床面跟踪是否贴合可见标线。
3. **右下角落点 minimap 自适应缩放**，让高分辨率视频中的落点分布更清晰。

## 本轮已合入实现（基于 leader HEAD 复核）

### 1. API / sidecar 已支持多关键帧

- `app.py`
  - 新增 `_canonicalize_calibrations_payload()` / `_calibrations_equal()`。
  - `/api/video/trampoline/start` 现在支持：
    - 新格式 `calibrations[]`
    - 旧格式 `corners`（自动归一化为 frame 0 单关键帧）
  - sidecar 写入字段扩展为：
    - `frame_index`
    - `time_s`
    - `corners_px`
    - `calibrations`
- 兼容策略保持为 additive：旧调用方不必立即迁移。

### 2. 前端已支持分析前视频预览 + 多关键帧补标

- `templates/video_analysis.html`
  - 增加“添加当前帧标定”“保存/更新关键帧”等入口。
- `static/js/video_analysis.js`
  - 支持从预览视频抓取当前帧。
  - 支持关键帧列表渲染、编辑、删除、重新进入补标。
  - start 请求提交 `JSON.stringify({ video_id, calibrations })`。
- `static/js/trampoline_calibration_geometry.js`
  - 继续承担 content-rect 坐标换算，保证 letterbox/portrait 场景下点击仍映射到原始视频像素坐标。

### 3. BedTracker 已扩展关键帧 / marker line 能力

- `trampoline/bed_tracker.py`
  - 新增 calibration 归一化与校验逻辑。
  - `from_sidecar()` 已读取 `calibrations[]`。
  - 配置中新增 `BED_KEYFRAME_TRANSITION_FRAMES = 20`，用于关键帧过渡平滑。
  - 新增 marker line 检测与附加诊断/输出字段。
- `trampoline/config.py`
  - 已包含关键帧过渡相关配置。

### 4. Overlay 已支持 marker line 与 adaptive minimap

- `trampoline/overlay.py`
  - `draw_trampoline_overlay()` 会读取并绘制 `marker_lines`。
  - `draw_marker_lines()` 使用青色/洋红色区分线段。
  - `draw_bed_minimap()` 已从固定 `150x85` 改为按 `ref=min(w,h)` 自适应缩放，并带 min/max clamp。

## 复核结果

### 通过项

已在 leader HEAD 上复核到以下行为/实现痕迹：

- 多关键帧 payload 与 sidecar 兼容路径已落地。
- 前端关键帧补标 UI 已接线到 start API。
- overlay 已包含 marker line 绘制与 adaptive minimap。
- 以下验证通过：

```bash
node tests/test_trampoline_calibration_geometry.mjs
PYTHONPATH=. pytest tests/test_trampoline_api.py -v
PYTHONPATH=. pytest tests/test_trampoline.py -v
```

### 阻塞项 / 复核发现

当前 leader HEAD **尚未稳定**，存在一个明确回归：

- `PYTHONPATH=. pytest tests/test_bed_tracker.py -v` 失败（10 failures）。
- 失败根因：`trampoline/bed_tracker.py` 的 `BedTracker.__init__` 中引用了不存在的方法 `_processing_frame_for_calibration`。
- 该问题会导致直接构造 `BedTracker(...)` 的既有测试全部在初始化阶段报 `AttributeError`，因此当前实现还不能视为 fully verified。

错误位置（复核时看到的堆栈）：

- `trampoline/bed_tracker.py:533`

影响面：

- `tests/test_bed_tracker.py` 中已有基础映射、低置信输出、LK/ORB 回归用例均被初始化异常拦截。
- 这说明本轮功能虽然大部分接口/前端/overlay 已接上，但 **BedTracker 的回归稳定性还需要再修一轮**。
