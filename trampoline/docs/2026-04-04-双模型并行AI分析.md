# 双模型并行 AI 分析

**日期:** 2026-04-04

## 需求

用户测试发现 qwen-plus 回复快但质量一般，qwen3.6-plus-2026-04-02 回复慢但质量好。需要同时启用两个模型：快模型流式输出到前端保持用户参与感，慢模型在后台并行运行，完成后用其高质量结果填充结构化卡片。

## 架构

```
用户点击"开始 AI 分析"
  → SSE 端点同时启动两个模型：
     ┌─ 主线程：qwen-plus (stream=True) → chunk events → 前端实时文本
     └─ 后台线程：qwen3.6-plus-2026-04-02 (stream=False) → 完整结果
  → 快模型流完 → fast_done event → 前端显示"正在生成高质量分析..."
  → 慢模型完成 → done event（用慢模型 sections）→ 卡片渲染
  → 慢模型失败 → 回退快模型结果 → done event (source=fast_fallback)
```

## 修改文件

| 文件 | 修改 |
|------|------|
| `trampoline/llm_service.py` | 新增 `resolve_models()` 返回 (fast, quality) 模型名；`stream_llm_analysis()` 增加 `model` 参数；新增 `run_llm_analysis_sync()` 非流式同步调用 |
| `app.py` | SSE `generate()` 重写：后台线程运行慢模型、主线程流式快模型、新增 `fast_done` 事件、`done` 事件带 `source` 字段 |

| `static/css/video_analysis.css` | 新增 `.llm-quality-waiting` 琥珀色缩放脉冲动画 |
| `tests/test_llm_service.py` | 新增 `TestResolveModels`、`TestRunLlmAnalysisSync` 测试类 |

## 环境变量

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `QWEN_FAST_MODEL` | `qwen-plus` | 快速流式模型 |
| `QWEN_MODEL` | `qwen3.6-plus-2026-04-02` | 高质量模型 |

## 线程安全

- 后台线程只做网络 I/O（GIL 友好），写入共享 dict 一次
- 主线程在 `thread.join()` 后读取，无竞争
- daemon=True，连接断开时 generator 被 GC，线程随进程退出
