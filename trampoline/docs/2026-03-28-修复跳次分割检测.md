# 修复跳次分割检测

**对应 commit:** f0aea3f
**日期:** 2026-03-28

## 问题

跳次分割完全不工作：JUMPS 始终显示 0，PHASE 始终显示 FLIGHT。

## 根因分析

5 个 bug 共同导致：

1. **速度阈值过小**：`LANDING_VEL_THRESHOLD=0.002`、`TAKEOFF_VEL_THRESHOLD=-0.003`，但归一化坐标下实际速度为 0.01–0.15，阈值偏低约 10 倍。
2. **Bootstrap 陷阱**：初始 phase 为 `"unknown"`，任何轻微上升运动即触发 `velocity < -0.003` → phase 锁定为 `"flight"`，无法退出。
3. **脚踝范围追踪器不重置**：`_ankle_y_max` 在整个视频中单调增长，`ankle_near_max` 条件（97% 的全局最大值）很快变得不可能满足。
4. **帧号不匹配**：`analyzer.py` 使用独立的内部计数器，与视频实际帧号脱节。
5. **速度未按时间归一化**：除以帧数窗口而非实际时间，不同帧率视频产生不同量级的速度值。

## 修复内容

| 文件 | 修改 |
|------|------|
| `trampoline/config.py` | 速度阈值放大 5 倍（0.002→0.01），删除 `CONTACT_ANKLE_Y_RATIO`，新增 `ANKLE_Y_EMA_ALPHA` |
| `trampoline/jump_detector.py` | 初始 phase 改为 `"contact"`；速度除以 `VELOCITY_WINDOW/fps`（时间归一化）；用 EMA 跟踪脚踝基线替代全局 min/max；删除 bootstrap 逻辑 |
| `trampoline/analyzer.py` | `process_frame()` 接受并传递 `frame_idx` 参数 |
| `video_processor.py` | 传递 `frame_count` 给 `analyzer.process_frame()` |
| `tests/test_trampoline.py` | 更新初始 phase 断言 |
