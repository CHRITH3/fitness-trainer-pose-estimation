# 蹦床标定回归与模块化

## 背景

本轮工作承接 2026-04-18 的关键帧标定补标实现，目标不是新增产品能力，而是完成两件收尾工作：

1. **A：补齐自动回归测试**，锁住“上传 trampoline 视频后进入待标定态”的关键接口与页面契约。
2. **B：将 trampoline 标定前端逻辑从 `video_analysis.js` 中拆出**，降低再次出现 UI 状态漂移、按钮职责混乱、模板/JS 脱节的风险。

## 本轮改动

### 1. 自动回归测试补强

- `tests/test_trampoline_frontend_contract.py`
  - 保留 JS `getElementById(...)` 与模板 `id="..."` 的对齐检查。
  - 新增 trampoline 页面契约测试，校验页面包含：
    - pending calibration UI 节点
    - `trampoline_calibration_geometry.js`
    - `trampoline_calibration_ui.js`
    - `video_analysis.js`
- `tests/test_trampoline_api.py`
  - 新增上传接口契约测试，校验 `/api/video/upload` 在 trampoline 模式下返回：
    - `status=uploaded_pending_calibration`
    - `first_frame_image`
    - `first_frame_b64`
    - `image_size`
    - `video_fps`
    - `total_frames`
    - `corner_order`
- `tests/test_trampoline_calibration_ui.mjs`
  - 为新拆出的前端标定模块增加纯函数级测试，验证按钮启用状态与草稿/状态文案。

### 2. 前端标定逻辑模块化

- 新增 `static/js/trampoline_calibration_ui.js`
  - 负责 trampoline 待标定阶段的独立控制器逻辑：
    - 进入 pending calibration
    - 草稿帧/首帧初始化
    - 当前帧截图
    - 床面四角点击与画布绘制
    - calibration 列表、选中、高亮、删除
    - 保存当前标定
    - 提交 `/api/video/trampoline/start`
- `static/js/video_analysis.js`
  - 删除大段 trampoline 标定内联逻辑。
  - 改为在 trampoline 模式下初始化 `TrampolineCalibrationUI.createController(...)`。
  - 主文件继续负责：
    - 通用上传流程
    - 分析轮询
    - LLM/报告/统计面板
    - 在标定提交成功后启动分析轮询
- `templates/video_analysis.html`
  - 增加 `trampoline_calibration_ui.js` 脚本引入，加载顺序为：
    1. `trampoline_calibration_geometry.js`
    2. `trampoline_calibration_ui.js`
    3. `video_analysis.js`

### 3. 样式清理

- `static/css/video_analysis.css`
  - 删除旧 trampoline keyframe UI 残留样式。
  - 保留当前 `.keyframe-row` 流程所需样式，并补充 `.keyframe-row.active` 高亮。

## 结果

- “保存/更新当前标定” 与 “开始分析” 的职责继续保持分离。
- 前端待标定逻辑不再混杂在 `video_analysis.js` 主文件中，后续维护范围更清晰。
- 页面脚本、模板 DOM、上传返回 payload 三者之间的关键契约已被自动化测试锁住。
- 未新增依赖，后端接口 shape 未变。

本轮完成后，已通过以下验证：

```bash
node --check static/js/video_analysis.js
node --check static/js/trampoline_calibration_ui.js
node tests/test_trampoline_calibration_geometry.mjs
node tests/test_trampoline_calibration_ui.mjs
pytest tests/test_trampoline_frontend_contract.py tests/test_trampoline_api.py tests/test_bed_tracker.py -q
```

结果：

- `trampoline calibration geometry tests passed`
- `trampoline calibration ui tests passed`
- `27 passed`

此外还做了本地链路 smoke check：

- `GET /video_analysis?mode=trampoline` 返回 200，且页面包含待标定 UI 与三段脚本。
- `POST /api/video/upload`（trampoline）返回 `uploaded_pending_calibration`，且包含首帧图像与 `corner_order`。

## 结论

本轮收尾后，蹦床视频上传到待标定阶段的关键路径已经具备两层保护：

1. **行为层保护**：上传接口与页面契约有自动化回归测试。
2. **结构层保护**：标定 UI 已独立模块化，降低再次因混合逻辑引发黑屏、按钮错连、状态错乱的概率。

后续如果还要继续演进这条链路，优先在 `trampoline_calibration_ui.js` 内增量修改，并保持当前契约测试同步更新。
