# 修复 AI 分析断连

**对应 commit:** （本次）
**日期:** 2026-04-04

## 背景

用户反馈：运行 `app.py` 后，网页端上传视频并完成 MediaPipe 分析没有问题，但点击“开始 AI 分析”后前端只显示“连接中断”，无法得到千问分析结果。

用户补充说明：在仓库外的 `/home/chris4/workspace/qwen_test/model_switch_test.py` 中，已经验证 DashScope/Qwen 模型本身可连通。

## 排查结论

根因不是 MediaPipe 或视频分析子进程，而是 LLM 分析链路存在两处问题叠加：

1. 后端 SSE 接口与用户测试脚本使用的鉴权环境变量不一致。
   - 用户测试脚本优先读取 `DASHSCOPE_API_KEY`
   - 项目原实现仅检查 `QWEN_API_KEY`
   - 当 Flask 进程未按原约定注入 `QWEN_API_KEY` 时，`/api/video/llm_analysis/<video_id>` 会直接返回错误

2. 前端 `EventSource` 错误处理过于粗糙。
   - 前端将所有 `onerror` 都渲染为“连接中断”
   - 这样会把真实后端错误与 SSE 终止事件都混成同一提示，掩盖具体原因

## 修改内容

### 1. 统一 API Key 解析逻辑

修改 `trampoline/llm_service.py`：

- 新增 `resolve_api_key()`
- 支持按顺序读取：
  - `QWEN_API_KEY`
  - `DASHSCOPE_API_KEY`
- `stream_llm_analysis()` 改为复用该解析逻辑

这样可以兼容项目内原有命名和用户外部验证脚本的环境变量命名。

### 2. SSE 接口统一返回流式错误消息

修改 `app.py` 中的 `/api/video/llm_analysis/<video_id>`：

- 为以下可预期失败场景统一返回 SSE 格式的 `type=error` 消息，而不是直接返回普通 JSON/HTTP 错误：
  - `video_id` 不存在
  - 不是 trampoline 模式
  - 视频分析尚未完成
  - LLM 服务导入失败
  - 未配置 `QWEN_API_KEY` 或 `DASHSCOPE_API_KEY`

这样前端可以拿到具体错误文案，而不是只触发连接失败回调。

### 3. 前端补充 SSE 终态判断

修改 `static/js/video_analysis.js`：

- 点击“开始 AI 分析”前，先关闭旧的 `EventSource`
- 新增 `llmStreamFinished` 状态
- 收到 `done` 或 `error` 消息后标记终态
- `onerror` 中先判断是否已经进入终态，避免正常结束时误报“连接中断”

## 测试与验证

执行并通过：

- `python -m pytest tests/test_llm_service.py -q`
- `python -m py_compile app.py trampoline/llm_service.py`
- `node --check static/js/video_analysis.js`

另外补充了 `tests/test_llm_service.py` 中的 API key 解析单测，覆盖：

- 优先使用 `QWEN_API_KEY`
- 缺失时回退到 `DASHSCOPE_API_KEY`
- 两者都不存在时返回空字符串

## 影响范围

- 仅影响 trampoline 模式下的 LLM 解释层
- 不影响 MediaPipe 骨架分析
- 不影响 fitness 模式普通视频分析
- 不影响视频处理子进程输出逻辑

## 用户侧结果

修复后：

- 如果千问分析正常，前端应显示流式文本并最终切换为结构化卡片
- 如果后端存在配置或业务错误，前端会显示具体错误信息，不再统一表现为“连接中断”
